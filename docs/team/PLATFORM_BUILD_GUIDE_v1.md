# AR 平台搭建指南 v1(员工手册版)

> 写给每一个加入这个项目的人。你不需要金融背景,也不需要是资深工程师——
> 你需要会用 AI 帮你写代码(vibe coding),会读大白话,会按验收标准交活。
> 本手册解释:我们在造什么、为什么、每个板块是干嘛的、数据怎么流、你怎么干活。
>
> 维护人:Junyan(产品与研究决策)+ Claude(架构与审核)。
> 版本:v1,2026-07-27。学长(PM/审阅者)意见每周消化进本手册的修订记录。

## 0. 一句话:我们在造什么

**一个私有的买方研究平台**:它每天自动收集市场数据 → 生成研究证据 → 人(Junyan)做全部买卖决策 → 平台记录每一笔的逻辑和结果 → 每周复盘改进。

三条铁律,任何代码任何页面都不许违反:

1. **AI 只出证据、信号、姿态,永远不出买卖指令。** 页面上永远不出现"应该买/卖"。每个输出末尾带一句:"不是买卖指令;研究信号,human executes."
2. **样本不到 30 个,不谈胜率、不谈 alpha、不谈"稳定赚钱"。** 我们已经亲手杀死过 5 个量化策略族(全部通不过统计检验),诚实是这个平台唯一的护城河。
3. **账本只有一份。** 信号账本 = `paper_signal_log.json`,资金账本 = `model_fund/`,论文登记 = `registered_court.json`。任何新功能都不许发明第四本账。

## 0.5 我们的定位(为什么长这样)

- **A 为体**:先是自己人用的研究工具,追求研究效率和纪律执行;
- **C 为皮**:但从第一天就要**美观、能讲故事**——打开它的人(未来的投资人、导师、伙伴)三分钟内能看懂"这个系统在做什么、凭什么可信";
- **B 为将来**:产品化(对外服务)后置,但架构上不给自己埋雷(数据契约、模块边界现在就画清楚)。

2026 年 4 月我们写下的自诊断至今有效,是全平台的北极星:
**"我们的问题不是缺功能,而是缺闭环。"** 每个新功能上线前先回答:它挂在闭环的哪一环?
闭环 = 数据 → 假设 → 登记 → 执行门 → 判分 → 复盘 → 改进。挂不上的功能不做。

## 1. 模型主干:三条线(structure tree,不许丢)

```
                    ┌─────────────────────────────┐
                    │   闭环:数据→假设→登记→执行门→判分→复盘→改进   │
                    └─────────────────────────────┘
   ┌───────────────┬───────────────────┬──────────────────┐
   │ A 研究线        │ B 执行线            │ C 宏观线(新)      │
   │ Core Thesis    │ Execution Gate     │ Macro / S&T      │
   ├───────────────┼───────────────────┼──────────────────┤
   │ 盘前帧          │ 哨兵与双层线         │ 世界时事事件流      │
   │ 轮动面板        │ 两票制下单           │ 分级宏观提醒        │
   │ factpack/决策书 │ 模型基金账本         │ 事件→假设→判分      │
   │ 判分池与周报     │ SMC 图表工作台(USP) │ (先B级轮询后A级推送) │
   └───────────────┴───────────────────┴──────────────────┘
```

- **A 研究线**:回答"买什么、为什么"。从全市场扫描到单票深研,产出证据包和研究姿态。
- **B 执行线**:回答"什么时候、怎么执行、错了怎么办"。含纪律引擎(双层线、执行窗口)和 **SMC 图表工作台——我们的独有 Alpha 所在**(见 §3.7)。
- **C 宏观线**:回答"世界正在发生什么、对我们的持仓和假设意味着什么"。模拟一个 S&T(sales & trading)台子的信息流。
- 量化实验室(Quant Lab)现阶段**暂停**(5 族 0 幸存的裁决记录在 `docs/strategy/QUANT_*_VERDICT_*.md`),将来从图表工作台里重新长出来,不单独立线。

## 2. 平台最终长什么样(呈现方式)

一个**深色金融终端风格的网页应用**(手机也能看),部署在 GitHub Pages 上,任何时候打开:

- **首页 = 当日驾驶舱**:顶部一行市场状态(市场门 + 前兆灯 + 宏观红黄蓝),中间模型组合当日状态卡,下方今日观察点列表。设计基准:彭博终端的密度 × Notion 的可读性。
- **七个页面**(v1 全部要有,见 §3);
- **一条叙事线**:任何访客从首页开始点三次,就能走完"系统怎么想(盘前帧)→ 系统怎么做(交易组合每笔逻辑)→ 系统学到了什么(周报复盘)"的完整故事。这就是 C(展示)的要求:**平台自己会讲自己的故事**。

美学规范(员工必读):
- 统一设计 tokens(`web/src/theme.ts`):背景 #0B0E14 系,涨红跌绿按 A 股习惯,强调色琥珀,等宽数字字体;
- 禁止五颜六色的仪表盘堆砌;每页回答一个问题,页面标题就是那个问题的大白话;
- 所有数字带单位与时间戳;数据缺失显示"DATA_BLOCKED(缺什么)",**永远不编数字**。

## 3. 七个功能板块(大白话逐个讲)

### 3.1 模型组合当日状态 —— "基金今天怎么样了?"
一句话:一支 100 万虚拟人民币的模型基金,每天收盘后记账,这页展示它的净值曲线、
现在拿着什么、现金多少、今天赚亏多少。
- 数据源:`experiments/execution_tracker/model_fund/`(fund.json / nav_history.json / orders.json)
- 关键规则:这是 **paper(纸面)基金**,页面必须标注 paper_only;真实资金的记录(human_shadow)分开显示,永不混算。

### 3.2 交易组合与每笔逻辑 —— "每一笔交易为什么做?"
一句话:每笔交易一张卡片,像病历一样完整:为什么进(thesis 票 + timing 票)、
在哪进、两条线在哪(论文线/灾难线)、现在怎么判、结果如何。
- 数据源:orders.json + decision_log.json + registered_court.json + paper_signal_log.json
- 大白话解释两票制:**买入需要两张票**——"这公司值得研究"(研究票)和"现在这个价位技术上合法"(时机票),缺一张就只能观察不能下单。
- 大白话解释双层线:每笔持仓两条线——**论文线**(破了 = 触发五项检查的复核程序,不是自动卖)和**灾难线**(成本-12%,破了无条件走,没有任何借口)。

### 3.3 盘前帧 —— "开盘前,世界发生了什么?"
一句话:每天开盘前自动生成的一屏:隔夜美股/半导体/A50 锚点、前兆灯(资金轮动预警)、
市场门状态、今天要盯的点。
- 数据源:overnight_anchor.json + lead_precursor.json + watch_dynamic.json(夜链自动产出)
- 大白话解释前兆灯:四盏灯监测"资金要搬家的前兆"(流出衰竭/邻域新钱/防御拥挤/龙头背离),≥2 盏亮 = 别在热门方向加仓,≥3 盏 = 允许小仓试探进入人工复核。灯是节奏控制,不是方向预言。

### 3.4 轮动面板 —— "钱在往哪搬?"
一句话:每晚统计所有板块的主力资金连续流向(连续 3 天以上流入的板块置顶),
并用统计学验证"这种连续性有没有预测价值"(答案:温和有,且我们敢公布置信区间)。
- 数据源:rotation_panel.json + rotation_stats.json + rotation_validation.json

### 3.5 宏观 S&T 面板 —— "世界大事直播间"(新建)
一句话:模拟一个交易台的信息流:重要新闻/数据/政策按红(立刻影响持仓)、
黄(影响本周假设)、蓝(背景知识)三级滚动展示,每条挂一个"影响假设"标签。
- **Phase B(先做)**:1-5 分钟轮询,零成本源:财联社电报(akshare)、东财快讯、
  交易所公告、央行/发改委 RSS、GDELT(全球事件库,免费)、yfinance 期货快照。
  轮询由已常驻的本地守望塔进程顺带执行 + GitHub Actions 盘外兜底。
- **Phase A(验证实用后)**:升级秒级推送(新闻 API + websocket + 小服务器,约 $50-150/月)。
- **最重要的设计决定**:事件不是拿来"看"的——每条事件结构化存储(时间戳/来源/分级/
  影响标签),**成为分析框架的输入**:事件 → 触发假设登记 → 进判分池 → 周报复盘。
  这就是"数据层完全纳入分析框架"的落地。

### 3.6 周报与复盘 —— "这周我们学到了什么?"
一句话:每周一页:市场发生了什么、模型改了什么、哪些判断被证伪、Memory 熔炼
(把教训蒸馏成下周可执行的规则)。
- 数据源:docs/team/weekly/*.md + weekly_recap.py 自动生成数据段
- 学长的审阅意见在这里闭环(见 §6)。

### 3.7 SMC 图表工作台 —— 我们的独有 Alpha(USP 核心)
一句话:**一张属于我们自己的 K 线图,把所有分析方法叠加在同一个画面上自动分析**——
这是市面上任何单一工具都不做的组合:
- **SMC(Smart Money Concepts)结构层**:自动标注宏观价格结构(BOS/CHoCH、订单块、流动性池);
- **纵向量能确认层**:成交量与价格趋势交叉验证,识别主力动向与长期趋势的一致/背离;
- **实时资金层**:主力净流入/流动性数据叠加在图上,观察"谁在买";
- **研究锚点层**:我们自己的论文线/灾难线/条款区/E1 事件直接画在图上。
- 为什么自建而不用 TradingView:TV 是 Junyan 个人的执行驾驶舱(继续用,已有 MCP 桥),
  但**平台的图必须能叠加我们私有的信号和账本数据**,TV 做不到。技术选型:
  `lightweight-charts`(TradingView 开源的图表库,免费、轻、够用)。
- 演进路径:v0 只读展示(K 线+量+我们的线)→ v1 SMC 自动标注 → v2 资金层叠加 →
  v3 在工作台里孵化我们自己的量化策略(重启 Quant Lab 的入口,仍受 30 样本铁律约束)。
- (远期:接入实盘交易接口在平台上直接操作。**红线预埋:即便将来接券商 API,
  每一笔真实订单必须人工逐笔确认,平台只准备订单要素,永不自动执行。**)

## 4. 数据怎么流(内部传导与分析来源)

### 4.1 现状诊断(为什么要重构)
平台今天是**两个互不相连的半球**:
- 云半球:GitHub Actions 定时抓数据 → `public/data/`(164 个 JSON)→ 旧版 Dashboard(7631 行单文件,盯着 6 只过时的票);
- 本地半球:Junyan 的 Mac 上 26 个引擎(夜链/哨兵/模型基金/判分)产出真正的资产,但**前端完全看不到**。
**GitHub 上部署的是最老的模型;真正的模型在本地。** 搭建工程的第一性任务 = 缝合两个半球。

### 4.2 目标数据流(单向,一图看懂)

```
 [数据源]          [引擎层]                [数据契约层]           [呈现层]
 Tushare ──┐   GitHub Actions 云抓取 ─┐
 东财/akshare ─┤   (盘后/盘前定时)      ├→ public/data/v2/*.json ─→ 新前端 web/
 yfinance ──┘                        │   (每个板块一份契约文件,     (只读,不写任何数据)
 财联社/GDELT → 本地夜链+守望塔 ────────┘    带 schema 说明文档)
 (宏观事件)      (账本/判分/哨兵,
                结算并入夜链)
```

规则三条,员工必须背下来:
1. **前端永远只读契约文件,永远不直接调外部 API、不写数据。**
2. **每个板块对应一份契约 JSON + 一份大白话字段说明**(放 `docs/contracts/`),前后端唯一接口。改契约必须先改文档再改代码。
3. **引擎写、前端读,单向流动。** 账本只在引擎层生长;`public/data/` 里旧的 164 个文件逐步归档,不再新增无主文件。

### 4.3 分析来源清单(现有资产,全部免费/已付费)
- 行情与财务:Tushare Pro(已付费,覆盖行情/财务三表/资金流/龙虎榜/筹码/两融/北向)
- 盘中资金:东方财富 push2 接口(免费)
- 海外锚点:yfinance(免费)
- 宏观事件(新增):财联社电报 via akshare、GDELT、官方 RSS(全部免费)
- 研究方法库:`docs/research/`(UNIFIED_RESEARCH_OS 宪法 v1.4、40+ 投资人视角框架、
  factpack/决策书模板、判分协议)——这些文档就是"分析方法的源代码"。

### 4.4 迁移问题的完整回答(技术与成本)
- 云端没有独立数据库:`public/data/` 在 git 仓库里,GitHub 和本地各一份,**不存在"搬数据"**;
- 要做的是:本地引擎产出按契约写入 `public/data/v2/` 并随夜链提交 → 新前端读取;
- 成本:现架构(Actions + Pages + Vercel 免费档 + Tushare 已付)新增 **¥0**;
  Phase B 宏观面板 **¥0-150/月**(可选付费源);Phase A 实时推送 **$5-20 服务器 + $20-100 新闻 API**;
  实盘接口远期另议(券商开户门槛,非现阶段)。

## 5. 工程路线图(给搭建者的施工顺序)

> 工作量按"1 人 × 每天 4 小时"估算。每个里程碑有验收标准,验收不过不进下一个。
> 在现有仓库 Alpha-Research 里演进,**不开新仓库**(历史、账本、流水线都在这里;
> 开新仓库等于亲手再造一次"两个半球")。

### M0 清障与地基(约 1 周)★朋友从这里开始

验收:页面数字与 `nav_history.json` 末行完全一致;每笔卡片能展开看到两票与双层线;

验收:早上 8:50 打开首页,能看到昨夜自动产出的完整盘前帧;前兆灯有大白话 tooltip。

### M3 宏观 S&T 面板 Phase B(约 1-2 周)

验收:一条真实红级事件从发生到上屏 ≤5 分钟;每条事件可一键"登记为假设"(写入判分池)。

### M4 周报复盘页 + 叙事首页打磨(约 1 周)
做什么:weekly md 渲染 + Memory 熔炼表;首页三步叙事动线;全站视觉统一 QA。
验收:一个从没见过项目的人,3 分钟自己看懂"系统怎么想→怎么做→学到什么"(拿真人测)。

### M5 SMC 图表工作台 v0(约 2-3 周)
做什么:lightweight-charts 接入(Tushare 日线契约),叠加成交量、论文线/灾难线/条款区;

验收:任一持仓票打开工作台,K 线+量+我们的三条线正确渲染;标注可保存并次日复现。

> M1-M5 每完成一个,Junyan 验收 + 学长过目,才进下一个。这条"分层独立上线,永不打包"

## 6. 团队工作法(所有员工适用)

### 6.1 vibe coding 规范
- 每个任务 = 一个 branch + 一个 PR;PR 描述里写:对应里程碑、验收标准逐条自查结果;
- **禁止 `git add .`**;只提交你的任务文件;秘钥(token/key)永不进代码,一律环境变量;
- AI 结对模板:"我在做 __(里程碑)的 __(任务),契约文件是 __,验收标准是 __,
  请帮我 __";先让 AI 解释再让 AI 写,看不懂的代码不合并;
- 每天收工前:PR 打草稿 + 一句话进度(做了什么/卡在哪/明天做什么)。

### 6.2 学长意见当周消化机制(固定节律)
- 周一:收集学长上周审阅意见(Notion 审阅面/口头),逐条编号;
- 周中:每条意见三选一处置——(a) 修合同/协议(走版本号)、(b) 转前端需求(进里程碑)、
  (c) 登记为研究假设(进判分池);
- 周五:周报固定一节《学长意见消化》,逐条写处置结果;**没有意见滞留超过一周**。
