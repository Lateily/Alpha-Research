## 1. 分工结论

Junyan 不承担 AIOS 编码、调试、日常任务拆解、普通 PR Review 或运行值班。Junyan 只保留产品方向、研究/资本/生产边界、核心规则、优先级、最终验收和 `main` 合并决定。

| 成员 | 主路径 | 负责解决的问题 |
|---|---|---|

| Reed | Agent Platform / Repository Intelligence / Skills | AI 如何定位代码和依赖、选择能力、调用模型与工具 |

### WP1：Session、跨端同步与安全恢复

**Primary：Eric；配合：Reed；Review：Jason。**

1. 检查 canonical repo、remote、branch、HEAD、dirty、工具、凭证状态和网络。
2. 输出 `session-state.v1`，禁止把缓存 `origin/main` 冒充实时 GitHub。
3. Mac/Windows 路径规范化，不依赖个人绝对路径。
4. 建 checkpoint/resume；恢复时重验 SHA、Authority、Task、PR、CLAIM、Context。
5. 检查 unpushed commit、orphan worktree、重复 clone 和本地唯一文件。
6. 网络/工具缺失时生成可交接 blocker，不静默降级。
7. 明确本地 `.ai-workspace/` 只存缓存、索引、run 和 checkpoint。

### WP2：Authority、Task 与工作流控制面

**Primary：Simon；实现配合：Reed；安全 Review：Jason。**

1. Authority Resolver：A0-A5、冲突、有效期、supersedes、核心路径。
2. Task Compiler：自然语言/Issue → `ai-task.v1`；缺字段 fail closed。
3. Task Registry：追加事件、幂等重放、唯一派生状态。
4. Workflow Resolver：按 task type/risk/module 选择模板与审批门。
5. `ai-program.v1`：Parent Issue、子任务 DAG、共享合同、PR/合并顺序。
6. owner/reviewer/依赖/预算/network/file scope 自动检查。
7. Final Merge Packet：只向 Junyan呈现结果、证据、风险和明确决策。
8. Reconciler 的规则定义：孤儿任务、过期 CLAIM、过早 DONE、无 Issue PR。

**对应 A-ID：** A-006、A-007、A-008、A-028、A-029；与 A-034 联合。\
**验收：** 一个跨模块需求能生成 task DAG、责任人、Review、集成门和最终验收包；冲突返回 `AUTHORITY_CONFLICT`，缺项返回 `SPEC_BLOCKED`。

### WP3：Repository Intelligence 与跨文件影响分析

**Primary：Reed；需求配合：Simon；Review：Jason。**

1. Symbol Graph：函数、类、模块、import、调用关系。
2. Data Lineage：producer → schema → artifact → consumer。
3. Test Map：requirement/guard → test → CI。
4. Ownership Map：path/contract → owner → reviewer → gate。
5. Decision Map：规则/文件 → Issue → PR → decision。
6. Incident Map：故障 → 根因 → 修复 → regression。
7. 输出 `change-map.v1`、confidence、未知项和 blast radius。
8. 为跨模块任务列出 producer/schema/consumer/test/owner 和回滚。
9. 建增量索引与 freshness；代码/合同变化后旧 map 变 STALE。

**对应 A-ID：** A-030、A-034。\
**验收：** 输入一个真实 Issue，系统能定位入口、依赖、消费者、测试、owner 和 active PR；低置信度必须返回 `CONTEXT_INCOMPLETE`，不得猜测。

### WP4：Context Broker、RAG 与知识合同

**Primary：Better；图谱接口：Reed；工作流配合：Simon；Review：Jason。**

1. 建 C0-C5 Context 分类与分阶段 Context Pack。
2. 建 module profiles：入口、合同、owner、测试、默认风险、Context 预算。
3. 文档 chunking、embedding、retrieval、rerank、citation 和 as-of。
4. 权威、当前任务、代码依赖、Issue/PR/Decision 和外部材料分别处理。
5. 外部材料标 `UNTRUSTED_DATA`，不能进入控制指令区。
6. 每段携带 source/location/reason/hash/freshness/trust/authority level。
7. Context precision、recall、sufficiency、stale 和 token budget Eval。
8. 先以 10-30 份批准文档做 bounded RAG，不导入整个仓库做大而全 RAG。
9. 构建 citation/as-of/missing/conflict 的正常与失败样例。

**对应 A-ID：** A-010、A-031。\
**验收：** 对真实任务只加载最少、最新、可追踪且足够的信息；main/合同改变后旧 Pack 自动 STALE；信息不足显式阻断。

### WP5：P5 Prompt、Team Style 与 Prompt Registry

**Primary：Better；安全共建：Jason；流程 Review：Simon。**

1. 固定 P0-P5 层级，禁止用 P5 覆盖 Authority 或 Policy。
2. 为代码建设、Review、诊断、RAG、跨模块、发布验收建立 P5 profiles。
3. Prompt 输出 `ROLE/CASE/PHASE/MISSION/METHOD/TOOLS/FORBIDDEN/OUTPUT_SCHEMA`。
4. 建 `prompt-registry.v1`，保存 profile/version/hash/适用 task type。
5. Prompt/model 变更触发对应 Eval，不使用旧结果冒充当前版本。
6. 将团队风格契约机器化：需求导向、结论先行、事实纪律、复盘与统一状态。
7. 验证 Reviewer Prompt 不继承 executor 工具和写权限。
8. 敏感 Prompt 只保存 hash，不进入公开日志。

**对应 A-ID：** A-026、A-036；与 A-035 联合。\
**验收：** 同一任务在不同 phase 获得不同方法，但权限始终由 A/Policy 决定；越权 Prompt 被测试拒绝。

### WP6：Agent Adapter、Skill Mesh 与能力路由

**Primary：Reed；Context 配合：Better；Review：Jason。**

1. Claude/Codex/Kimi/确定性 worker 使用统一 AgentAdapter。
2. 统一 input/output/error/timeout/retry/usage/model/prompt_version 接口。
3. Capability Registry 保存任务类型、权限、评测、成本和失败模式。
4. Skill Registry 声明 trigger、schema、tools、scope、network、risk、owner、Eval。
5. Skill Router 按 task/context/risk 路由，不按模型品牌硬编码。
6. Chain Compiler 组合原子 Skills；每个 Skill 可独立失败与回滚。
7. Tool Gateway 与 Jason 的 Policy Gateway 对接。
8. 未通过影子 Eval 的模型或 Skill 不进入默认生产链。
9. 保留版本、兼容性、deprecation 和 capability evidence。

**对应 A-ID：** A-001、A-013、A-014、A-032。\
**验收：** 新模型只需 adapter + capability record + Eval 接入；移除一个 Skill 时链路能明确失败而不是静默换行为。

### WP7：Policy、权限与安全护栏

**Primary：Jason；Authority 配合：Simon；平台配合：Reed；运行 Review：Eric。**

1. 文件范围、forbidden scope、路径逃逸和 protected paths。
2. 工具 allow/deny、网络 deny/allowlist、secret scan、日志脱敏。
3. risk、budget、timeout、production、data migration 和不可逆动作门。
4. prompt injection、恶意 PR、外部指令、scope escape、凭证滥用红队。
5. `POLICY_BLOCKED`、`AUTHORITY_CONFLICT`、`BUDGET_BLOCKED` 的结构化错误。
6. 执行前 gate、运行中 kill switch、执行后证据检查。
7. 高风险门配正向、负向、mutation 和 current-head CI。
8. Junyan reserved gate 只用于核心/宪法/高风险/最终验收，不扩张为日常审批。

**对应 A-ID：** A-009、A-027、A-028 安全部分。\
**验收：** 越界文件、恶意 Context、secret、未批准网络、超预算和权限提升都在副作用前被拒绝；删除门时测试因正确原因失败。

### WP8：Scheduler、Isolation、Retry 与 Runtime

**Primary：Eric；执行器配合：Reed；安全 Review：Jason。**

1. 依赖 DAG、就绪判断、并发限制与优先级。
2. CLAIM、lease、heartbeat、release、file-overlap lock。
3. branch/worktree/commit/run 隔离与工具/网络 sandbox。
4. idempotency key、retry 分类、backoff、timeout、cancel 和 cleanup。
5. checkpoint/resume；中断后不重复写数据或重复收费。
6. LOW/MEDIUM/HIGH/CONSTITUTIONAL 对应不同运行边界。
7. deterministic worker 与 LLM worker 的任务分派。
8. Windows/macOS/Linux 差异、容器化前置条件和故障注入。

**对应 A-ID：** A-011、A-012、A-015、A-016、A-033。\
**验收：** 重叠文件不能并行写；超时能强制停止并清理；同一输入重试不产生重复副作用；旧 checkpoint 不能绕过新 Policy。

### WP9：Evidence Chain、Verifier、Review 与 Human Gate

**Evidence infrastructure：Eric；质量规则：Jason；工作流：Simon；平台支持：Reed。**

1. `session/authority/task/workflow/change-map/context/prompt/run/artifact/verify/review/decision/handoff/memory` manifests。
2. 绑定 task/run/head SHA/base SHA/authority hash/context hash/prompt/model/policy/reviewer。
3. Diff-aware test planner 和 current-head validation。
4. 独立 Review 输出 severity/evidence/failure scenario/repair/residual risk。
5. 新 commit 自动使旧 CI、Context、Review 和 approval STALE。
6. Human Decision Gate 支持 APPROVE/REVISE/REJECT/DEFER/RETIRE。
7. Final Merge Packet 聚合给 Junyan，不要求其阅读所有运行日志。
8. 区分 DELIVERED/REVIEWED/APPROVED/MERGED/DEPLOYED/PRODUCTION_VALIDATED/DONE。

**对应 A-ID：** A-017、A-018、A-019、A-020。\
**验收：** 一个真实 PR 可从执行证据走到独立 Review 和 Junyan 最终验收；执行者不能自签；旧 SHA 证据不能通过。

### WP10：Harness Evals 与质量系统

**Primary：Jason；Context Eval：Better；平台测试：Reed；可靠性测试：Eric。**

### WP11：Observability、成本、报警与 SLO

**Primary：Eric；产品投影：Better；质量 Review：Jason。**
