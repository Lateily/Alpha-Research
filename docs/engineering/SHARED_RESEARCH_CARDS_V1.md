# Shared Research Cards V1

Authority: Junyan's ordered isolated recovery, finite source-gap closure, then
latest-card workbench integration. Existing production and shared services stay
unchanged. This is not a new model/provider, valuation approval or trading path.

Use the existing frozen inputs, persistent queue, actor/workspace/code binding,
bounded worker, output seals and cold-backup machinery. A distinct opt-in kind
research-cards-review consumes a distinct registered envelope, never a market
publication or a legacy earnings-review input. Operator registration supplies
independent library/pack/content/basis hashes; browser requests only choose a
registered snapshot ID and supply exact current workspace and code identity.
The service flag --shared-research-cards-v1 is explicit and default-off. Isolated
recovery opt-in --research-cards emits schema ar.isolated-recovery.v2 with the
single exact boolean research_cards_enabled; old recovery-v1 profiles and their
strict field/permission guards are unchanged and do not gain this feature.

The registered input copies four immutable trees: library, pack, content, basis.
Use each existing verifier and recomputation contract. Verify all original file
hashes before registration, every use, rendering, detail, archive query and cold
restore. Preserve producer identities; consumer identity is the new execution.
The four combined trees are capped at512 files/256MiB; all existing per-file,
per-tree, backup-index and global12MiB limits remain unchanged.
Registration interruption, orphan and partial copies spend existing capacity
and require reconciliation; never adopt unbound bytes as a new success.

The task only verifies/reopens frozen research and produces an independently
sealed metadata report/archive. It does not claim a new financial judgement or
recompute a prospective strategy. Source cutoff, research date, daily vintage,
producer version and task version stay separate. Historical company-action
BREAK, missing normal EPS/net cash/fair multiple and feedback NOT_SUPPLIED remain
unchanged. No zero imputation or automatic approval is allowed.

The page shows registered choices, task identity/logical steps, card statuses,
missing-field and reason-code metadata, citation locations and archive hashes.
Original PDFs, facts/response prose, financial values, raw quotes and research
report text remain DENIED while rights are UNVERIFIED/PRIVATE. A metadata-only
receipt may be downloaded; no permission upgrade is inferred from login/hash.
All authorities remain false, human review PENDING, WORKFLOW_DEBUG.

Add a separate versioned research-card-library endpoint and industry/taxonomy/
version/research-date/security AND query. Reopen only sealed task archives, never
mutate frozen research or silently mix their row schema with legacy results.
Unknown/stale/disconnected/version-changed views cannot submit or download.

Acceptance: exact-scope synthetic and retained-real registration/task/seal/query,
negative byte/scope/identity/rights/cold-restore regressions, original mutation
declarations unchanged, one final SHA complete offline CI and behavioral gate,
nonauthor independent review and desktop/mobile browser QA. No push, merge,
remote CI or current-service activation is implied. Actual two-human acceptance
remains DEFERRED; physical reboot/off-machine preservation are not attested.
# Request-Local Read Verification

Each HTTP read deeply verifies each referenced frozen input once, then checks
every output's binding and all four source inventories before and after metadata
projection. Reuse exists only inside that request; independent reads never use a
retained semantic cache. Public detail verification has no skip flag. Existing
actor lookups read their exact persisted binding without acquiring the queue
writer lock; missing actors retain atomic insert-or-ignore and refetch. These
changes do not extend the UI freshness window, SQLite wait budget, source limits,
rights or any human/production authority.

Common refresh and pending/detail refresh are independent single-flight readers.
Slow detail work cannot delay the next common poll. Both readers are disposed
together; late identity/workspace responses and explicit detail errors remain
fenced. The original fifteen-second freshness guard is unchanged.

Large material libraries are still scanned and hash-checked on every read. The
credential scanner uses necessary literal indicators before invoking the
unchanged detectors, including their Unicode case and escape behavior. No
cross-request result cache, file identity shortcut, or permission change is
used by this optimization.
