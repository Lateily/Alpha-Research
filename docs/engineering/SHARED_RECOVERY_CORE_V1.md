# Shared Recovery Core V1

Authority: Junyan's 2026-11-09 instruction to implement recovery, core missing-data
closure, then shared research cards, in that order. The existing blueprint and
module audit define the goal; the earlier instruction to proceed without repeated
planning questions remains applicable. This slice implements recovery first.

## Scope

Prepare a new isolated recovery capsule from an independently pinned, existing
shared backup. Restore original records and artifacts without credentials or
in-place migration; record backup and code identity. Reuse the accepted trusted
host bootstrap, environment/source/asset checks, bounded supervisor, and queue
seals. Do not weaken the old empty synthetic-runtime profile.

The capsule may enable registered materials, governance attachments and a pinned
research metadata library. Its read-only publication source, when supplied, is a
frozen independent directory whose complete bounded file inventory is pinned.
This proves the fuller service topology, not a live publisher subscription.
Only loopback ports 18000-18999 and the existing synthetic owner/member/origin are
permitted. Max unexpected restarts remains two; each rehearsal at most 300 seconds.
No arbitrary flags, commands, network/provider calls or shell are accepted.

The new profile uses a separate schema with exact fields and external SHA256.
An external backup pin is required before any destination creation. Backup v1/v2
validation and all original 12MiB/hash/seal/migration rules remain unchanged.
The source archive is retained; a partial failed recovery has no valid final
profile and is not resumed by overwriting files. A new root is required.

State changes during rehearsal are expected. Verify restored tables/artifacts
exactly before first start; subsequently verify the frozen source backup and
restoration provenance, not equality with the evolving database. Each restart
still rechecks code/environment/assets/resources and queue output seals.

## Non-Goals

No production/shared changes, real identity/ACL changes, launchd installation,
host restart, new backup of live state, external copy, source API, paid model,
U4/paper authority, push, merge or service cutover. A generated launchd template
is NOT_INSTALLED; cold process recovery is not physical reboot acceptance.

## Next Slices

Core data closure consumes pinned source receipts and persists precise gaps,
classification, next eligibility and approved result bindings without dispatching
market requests. Research cards then consume verified new sealed evidence via a
closed registered input, retain rights restrictions, and share the existing
task/result/query contracts. They do not turn missing financial inputs into zero
or a BREAK into a trading setup. Those slices follow recovery acceptance.

## Acceptance

TDD: valid backup/new root, wrong external pin, retained artifacts, credential
absence, existing/overlapping/symlink paths, changed resource/code/environment,
unknown flags, duplicate supervisor, bounded restarts, cold supervisor restart,
existing completed jobs reopening and interrupted attempt recovery.

Use one clean final SHA for complete offline CI, all retained plus new behavior
mutations, real retained-backup restore/service rehearsal and fresh nonauthor
engineering review. Mark host reboot/off-machine/two-human/remote-CI separately.
